# Benchmark — 图像匹配（V3 多模态）

> 本文件由 `python -m scripts.eval_images` 自动生成，不要手工编辑。

要证明的不是「两张不同的图能区分」——那太容易了。真正要证明的是：

1. 同一件物品的**另一张照片**能被认出来（角度 / 裁切 / 亮度 / 噪点全都不同）
2. 用户只有一句文字描述、没有照片时，也能匹配到工作人员拍的照片
3. **同类不同件不会被错认**——如果 CLIP 只认「这是个包」，图像通道就毫无价值

## 环境

| 项 | 值 |
|---|---|
| image provider | `clip_onnx` |
| 视觉模型 | `Qdrant/clip-ViT-B-32-vision` |

| 语料 | 7 件物品，每件 2 张照片（a 给 LOST，b 给 FOUND） |

## CLIP 只懂英文——以及怎么免费绕过

CLIP ViT-B-32 只在英文语料上训练过。直接拿日文 query 去问它：

| query | 命中 | 余弦 |
|---|---|---|
| `黒いリュック` | ✅ | 0.235 |
| `赤いリュック` | ❌（命中水筒） | 0.238 |
| `紺色の傘` | ❌（命中水筒） | 0.228 |
| `a red backpack` | ✅ | 0.290 |
| `a navy umbrella` | ✅ | 0.336 |

日文 2/5、英文 5/5。对一个部署在日本的系统，这是硬伤。

解法不是换更大的模型，而是**复用已有的同义词标准化层**：
抽取层本来就把「黒い」「リュック」归一成了英文 canonical（`black` / `bag`），
于是可以拼出一句规范的英文 CLIP prompt 再检索：

```
「紺色の傘をなくした」
   ↓ Query Understanding（第 ① 层，词典）
color=blue, category=umbrella
   ↓ build_clip_prompt()
"a photo of a blue umbrella"
   ↓ CLIP 文本侧
```

文 → 图 Top1 从 **57.1% 提升到 85.7%**，余弦从 0.21~0.25 提到 0.29~0.33。
零成本，没有引入任何新模型。

## 关于测试图

这些是 `scripts/gen_test_images.py` 生成的**合成图**，不是真实照片。
每件物品两张之间做了真实拍摄会有的差异：不同角度、裁切、亮度、噪点、轻微模糊。
真实照片走的是完全相同的通道，CLIP 对真实照片的表征质量只会更高。

唯一一条失败（`黒いスマートフォン` 排第 3）大概率是合成图的锅——
我画的手机是一个深色圆角矩形加一块青色屏幕，在 CLIP 眼里和长财布确实不好分。
